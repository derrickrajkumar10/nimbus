# NIMBUS citizen app: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Android Flutter citizen app described in `app/docs/design.md`, in the Deep tide style, with the photo-to-depth reveal as its centrepiece.

**Architecture:** A data layer behind one `NimbusApi` interface with two implementations: HTTP against the citizen API, and fixtures from bundled assets. One setting picks between them. Pure-Dart domain functions do the ranking, alert routing and copy. They're unit-tested without Flutter. Riverpod providers poll and cache. The screens are thin and share a small kit of Deep tide widgets: waves, round buttons, band chips, the depth figure and the map.

**Tech stack:** Flutter (stable), Dart 3, `flutter_riverpod`, `http`, `maplibre_gl`, `flutter_svg`, `firebase_core`, `firebase_messaging`, `flutter_local_notifications`, `shared_preferences`, `image_picker`, `flutter_image_compress`, `geolocator`, `uuid`, `flutter_localizations` with gen-l10n (ARB).

**Spec:** `app/docs/design.md`. **Mockups:** `app/docs/mockups/styles.html`, where section "2 · Deep tide" is the chosen style (open it in a browser). It was generated by `gen_styles.py`, which holds the icon paths, wave and figure geometry. Read it first, then `CONTEXT.md`, `contracts/README.md` and the "Citizen API" section of `api/README.md`.

## Global constraints

- Only edit `app/`. Requests for other lanes go into issues: #58 is `GET /hazards`, #59 is the CI job, #60 is the threshold nudge, #17 and #23 are the Verifier and Pathfinder.
- Never redefine a contract entity. Use the generated Dart classes, copied into the app by `tool/sync_contracts.sh` (Task 1). They need the nullable fix from PR #61, so until #61 merges, sync from `origin/derrick/contracts-dart-nullable`.
- The Android `applicationId` is `in.nimbus.app`. `android/app/google-services.json` is gitignored and never committed. Get it from the Firebase console, as Varun described.
- Every request carries `run_id`, either `live` or `replay-michaung`. Times shown to the user come from `sim_time` or `observed_at`, never `DateTime.now()`.
- Predicted risk is warm and observed water is blue or cyan. Never label a predicted Segment "flooded". `RiskBand.FLOODED` comes only from the API.
- No emoji anywhere in the UI. Icons are the app's own SVG line set (Task 2).
- Fonts are bundled: Outfit for Latin text, Noto Sans Tamil for Tamil. They're never fetched at runtime.
- Deep tide colours (exact):
  - sky `#5F8FAE` → `#3B6E93` → `#1C4A75` → deep `#0A1F44`
  - waves `#3E78A0 #2E6690 #22557F #18456E #10365E #0A2849`
  - text `#FFFFFF`, muted `#A9C6DB`, accent `#4FD1D9`, button `#2FA9B8`, SOS `#E8432A`
  - bands: low `#CFE3F0`, watch `#F2B34A`, likely `#FF7A57`, observed water `#59D8E6`
  - map: background `#0C2347`, roads `#183764`
- Respect `MediaQuery.disableAnimations`. Waves stop drifting, and the reveal jumps to its final state.
- Data source and API base URL come from `--dart-define=NIMBUS_API_URL=<url>`. Empty means fixtures. The base URL comes from SSM `/nimbus/api/citizen-url`, which Varun will post.

## Review focus

1. **The API is down or returns 5xx during polling.** Keep the last good data, show a small "offline · updated hh:mm" tag, and never crash or blank the screen. Test in Task 5.
2. **A Replay hasn't started.** `/reports` and `/sos` return 409 `run_not_started`. Show a screen that explains it, not a generic error. Tests in Tasks 11 and 14.
3. **A push is tapped when no place matches.** If `segment_id` matches no Saved Place, or the push opens a cold app, go to Home. Test in Task 4.
4. **Tamil text on a small phone.** At 320 dp width in the `ta` locale, Home and Place detail don't overflow. Test in Task 7.
5. **A place has no Segments, or a Segment has no risk row.** The place shows "No streets nearby" or "No data yet" instead of crashing. Test in Task 4.

### Task 8: The tide map, ward map and place detail

**Files:**
- Create: `assets/map/tide_style.json`, `lib/ui/widgets/tide_map.dart`, `lib/ui/screens/ward_map_screen.dart`, `lib/ui/screens/place_detail_screen.dart`

**Interfaces:**
- Produces:
  - `Map<String, dynamic> segmentsGeoJson(List<Segment> s, Map<String, SegmentRisk> risk)`: a FeatureCollection with `properties.band` and `properties.color` (from `bandColor` as `#rrggbb`).
  - `Map<String, dynamic> hazardsGeoJson(List<Hazard> h)`: points with `properties.radius_m`.
  - `TideMap({required List<Segment> segments, required Map<String, SegmentRisk> risk, List<Hazard> hazards = const [], LineString? route, GeoPoint? focus, double zoom = 15})`. It's a `MaplibreMap` wrapper that adds the GeoJSON sources and these layers: Segment casing (9 px `mapRoad`); band line (3.5 px, 4.5 px for likely); flooded line (8 px water plus a 16 px halo at 25%); a hazard circle (red, 4.5 px, with a dashed no-go ring); and the route (5.5 px accent plus a 14 px glow at 22%). ### Task 12: The reveal (centrepiece)

**Files:**
- Create: `lib/ui/widgets/depth_figure.dart`, `lib/ui/screens/reveal_screen.dart`
- Test: `test/ui/reveal_test.dart`

**Interfaces:**
- Consumes: `ReportFlow` states, `waterFraction`, `thresholdStory`, `TideMap`, `TideBackground`, and `nimbusIcon`.
- Produces `DepthFigure({required double waterFraction, required Animation<double> progress})`. It draws a standing figure (head, torso, arms, legs as in `body()` in `app/docs/mockups/gen_styles.py`, in a 100×220 box) *behind* layered water. The water's top is at `waterFraction` × the figure height × `progress`, with a gentle slosh (a damped sine of 3 px over 600 ms). Dashed reference lines mark the ankle and waist.

**Choreography**, driven by one `AnimationController` per stage:
1. **Verifying:** the photo thumbnail shrinks into a rounded frame. "Verifying…" and concentric ripples loop until `Verified`, with a minimum of 1.2 s.
2. **Water rises** over 1.4 s (`Curves.easeOutCubic`) to `waterFraction(reading.depth)`, then slosh. The depth label (`kneeDeep` etc.) and its Tamil fade in over the water, 36 pt Outfit 600.
3. **Vehicles** drop in with a 250 ms stagger: two-wheeler, car, ambulance, from `reading.passable`, each with a green check or red cross badge.
4. **Hazards:** each one in `reading.hazardsSeen` shows a red warning that pulses twice (600 ms).
5. **Pull back** over 1.5 s: the frame cross-fades to a `TideMap` focused on the Segment, showing it as water with the hazard rings. Then the threshold line runs: if `learned`, "You taught the map." counts from `from` to `to` mm over 1.2 s; otherwise it shows `confirmedPrediction`.

`StillChecking` and `Failed` swap stages 2–5 for a calm message on the tide, with Home and Try again buttons. With `disableAnimations`, it jumps straight to the final frame.
